## 3. 核心断言

### 3.1 冻结 Repository 接口

按后端 mockRepository.js 冻结签名断言：

```js
// getNews(page, pageSize) 返回结构必须是：
{ items: [{ title, desc, date:'YYYY-MM-DD', slug, pinned }], total, page, pageSize }
// 排序：is_pinned DESC → publishedAt DESC → sort_order ASC → id DESC
```

验证点：
- `getSite/getHome/getAbout/getBusiness/getProjects/getNews/getRecruitment` 全部可注入假客户端，不依赖 Prisma 引擎。
- 公告置顶优先于任何时间排序（`置顶公告` 在 `最新公告` 之前）。
- `getNews` 只返回 `status=published`，`draft/offline` 不外泄。
- 分页在数据库侧完成（`skip/take`），不是内存 slice。

### 3.2 种子隐私约束

- 全仓库检索个人姓名、财务词（银行/账户/开户行） → **0 命中**。
- `mock-data.json` / `initial-data.json` 不出现银行、账户、开户行。
- 正式 `initial-data.json` 的 `contactEmail` 为空、`posts: []`。

### 3.3 多版本 DDL 一致性

静态文本解析四份定义（Prisma / migration.sql / schema.sql / 数据字典）的字段名、枚举值、索引名、is_pinned 字段，全部一致。

## 5. 已知限制

1. **假客户端不模拟 Prisma 全部行为**：只覆盖 Repository 用到的 `findUnique/findMany/count/upsert`，`$transaction`、`$queryRaw` 等一期未用到的操作不实现。
2. **分页上限 100**：`normalizePagination` 把 pageSize 钳到 100，服务层如果需要拉更多得走下一页循环。
3. **Prisma 枚举在 MySQL 返回字符串**：`status/published/isPinned` 字段通过 Json.parse 归一化，真实生产验证时如果发现类型不符再加一层 typeof 检查。
4. **生产账号权限**：文档给出的是本地最小权限示例，生产账号由服务器负责人单独配置，禁止使用 root。
