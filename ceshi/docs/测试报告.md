## 4. 关键验证点

### 4.1 数据访问层

- `GET /site`：字段映射正确，`contactEmail = null` 时输出 `""`（不返回 null），未启用的外链被过滤，图片路径不进入公开接口。
- `GET /home`：`hero` / `statement` 支持 MySQL JSON 字段被驱动返回字符串的情况；JSON 损坏时降级为空数组与空串，不抛 500。
- `GET /about`：使命、文化、准则、协作、团队、路径、地点结构完整；**不包含** `members` 与成员个人资料；团队职能只返回 `id/title/text/tags`。
- `GET /business`：只返回 `is_active = true`，按 `sort_order` 升序，`where` 与 `orderBy` 参数经断言确认。
- `GET /news`：只查 `status = 'published'`，`draft` / `offline` 不外泄；按发布时间倒序；日期输出 `YYYY-MM-DD`。
- 分页：默认 1 / 20，`pageSize` 上限 100，自定义分页偏移正确。
- 非法文章类型抛 `ApiError(400, 40001)`，不会静默返回空列表。
- `GET /projects` / `GET /recruitment`：无已发布内容时 `status = 'preparing'` + 空数组 + 栏目占位文案；有内容时 `online`。
- `GET /about/team`：仅职能，符合「一期不展示成员资料」的约束。

### 4.2 中间件

- CORS 只回显白名单 Origin；非白名单不返回 `Access-Control-Allow-Origin`；`OPTIONS` 预检 204 且不进入业务路由。
- 访问日志输出单行 JSON，5xx 标记 `error`，`/health` 跳过。
- 参数校验结果写入 `req.validated.query/params/body`，数字完成类型转换，未知字段被裁掉；错误携带 `details.field`。
- 统一错误：`{ code, message, data: null }`；Prisma `P2025 → 40401`，非法 JSON → `40001`，未知异常 → `50000` 且不泄漏内部错误信息；响应已发出时不重复写入。

### 4.3 种子数据

- `mock` 与 `initial` 结构一致，可被同一导入脚本复用。
- `mock` 明确标记测试内容，覆盖 3 种文章类型与 3 种状态、含未启用的方向与外链，可验证全部过滤逻辑。
- `initial` 不含银行、账户、开户行、身份证、手机号等财务/隐私词，也不含成员姓名。
- 正式数据包含组织全称、信用代码、地址、简介、使命、文化与准则、团队整体介绍、4 条研究方向、Skill Hub 外链；公告/成果/招聘为空数组。

### 4.4 结构一致性

- `schema.prisma` 的 5 个模型与 `schema.sql`、`migrations/20261104000000_init/migration.sql` 的表名、列名逐一相等。
- 所有 JSON 字段在 MySQL 中均为 `JSON` 类型。
- `PostType` / `PostStatus` 枚举与 Repository 常量一致。
- 种子文件字段、导入脚本字段白名单与 Prisma 模型字段一致，避免改名后静默丢字段。
- 主键、唯一键、查询索引均在 SQL 中声明。

## 6. 已知限制与风险

1. **未做真实 MySQL 集成测试**：Repository 使用内存假客户端验证逻辑，SQL 正确性由结构一致性测试与 DDL 审查保证，仍需联调环境实测。
2. **Prisma CLI 未运行**：`prisma validate` / `migrate` 依赖二进制下载，当前网络不可用；迁移 SQL 与 `schema.sql` 已人工对齐并有测试兜底，但首次真实迁移需在可联网环境执行一次确认。
3. **并发分页**：`total` 与列表分页在两次查询间若有新发布内容，可能出现轻微不一致；一期公开只读、内容更新频率低，可接受。
4. **MySQL 版本**：JSON 类型要求 5.7+，文档约定 8.0+；低版本需改为 TEXT 并自行解析。
5. **生产账号权限**：文档给出的是本地最小权限示例，生产账号由服务器负责人单独配置，禁止使用 root。
