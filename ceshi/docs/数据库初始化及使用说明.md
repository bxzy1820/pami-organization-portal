## 1. 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | >= 18.18（已在 v24.19 验证） | 运行 Prisma 与导入脚本 |
| MySQL | 8.0+ | 需要 JSON 类型与 `utf8mb4` |
| npm | 9+ | 安装依赖 |

一期不需要 Redis、对象存储、消息队列。

├─ seed/mock-data.json         # 模拟数据（测试内容）

## 3. 创建数据库和账号

以管理员身份登录 MySQL 后执行（密码请自行替换，不要写进仓库）：

```sql
CREATE DATABASE IF NOT EXISTS pami_portal
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'portal_user'@'localhost' IDENTIFIED BY '你的本地密码';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES
  ON pami_portal.* TO 'portal_user'@'localhost';
FLUSH PRIVILEGES;
```

> 生产环境不要复用这套账号，由服务器负责人单独配置最小权限账号。

## 5. 建表（两种方式，任选其一）

### 5.1 推荐：Prisma 迁移

```bash
cd backend
npm install
npx prisma generate
npx prisma migrate deploy
```

首次开发也可以用 `npx prisma migrate dev --name init`，它会同时生成迁移文件。

### 5.2 兜底：手工执行 DDL

```bash
mysql -u portal_user -p pami_portal < database/schema.sql
```

两种方式的表结构一致；已用迁移建表后不要再执行 `schema.sql`，以免结构漂移。

验证表是否创建成功：

```sql
USE pami_portal;
SHOW TABLES;
-- 期望：site_settings, business_directions, posts, external_links, media_files
```

## 6. 导入数据

### 6.1 开发 / 联调：模拟数据

```bash
cd backend
node ../database/scripts/import-data.js --set=mock --reset
```

- `mock-data.json` 全部内容标注「测试数据」，用于前后端并行开发。
- 包含 3 种文章类型、3 种内容状态，以及未启用的方向与外链，便于验证过滤逻辑。

### 6.2 正式初始数据

```bash
cd backend
node ../database/scripts/import-data.js --set=initial --reset
```

- 内容来自组织公开信息，不含成员资料和财务信息。
- 公告、成果、招聘暂不导入正式记录（`posts: []`），前端展示「内容正在整理中」。

### 6.3 导入行为

| 表 | 策略 |
| --- | --- |
| `site_settings` | 固定 `id = 1`，upsert，永远只有一行 |
| `business_directions` | 按 `code` upsert |
| `posts` | 按 `slug` upsert |
| `external_links` | 每次先清空再写入，避免重复 |
| `media_files` | 追加写入（一期不使用） |

`--reset` 会清空五张表后重新导入；不带 `--reset` 为增量导入。
脚本会打印每个表的行数，便于确认。

## 8. 与后端接口联调（交接给李悦涵）

Repository 已按 `docs/API接口文档.md` 的返回结构实现，Service 只需包装统一响应：

```js
import { siteRepository } from '../repositories/index.js'

export async function getSite() {
  const data = await siteRepository.getSite()
  if (!data) throw ApiError.notFound('站点信息未初始化')
  return data
}
```

| Repository 方法 | 对应接口 | 返回 |
| --- | --- | --- |
| `siteRepository.getSite()` | `GET /api/v1/site` | 站点信息；无配置返回 `null` |
| `homeRepository.getHome()` | `GET /api/v1/home` | `{ hero, statement }` |
| `aboutRepository.getAbout()` | `GET /api/v1/about` | `{ mission, culture, values, collaboration, team, journey, place }` |
| `aboutRepository.getTeam()` | `GET /api/v1/about/team` | `{ items }` |
| `businessRepository.getBusiness()` | `GET /api/v1/business` | `{ items, cooperation }` |
| `postRepository.getNews({ page, pageSize })` | `GET /api/v1/news` | `{ items, total, page, pageSize }` |
| `postRepository.getProjects()` | `GET /api/v1/projects` | `{ status, title, description, empty, plans, items }` |
| `postRepository.getRecruitment({ page, pageSize })` | `GET /api/v1/recruitment` | `{ status, title, description, empty, items, total, page, pageSize }` |

中间件接入顺序：

```js
import { createCommonMiddleware, errorHandler, notFoundHandler } from './middleware/index.js'

app.use(createCommonMiddleware())   // CORS + 访问日志
app.use(express.json())
app.use('/api/v1', routes)
app.use(notFoundHandler)
app.use(errorHandler())
```

参数校验示例：

```js
import { paginationSchema, validateQuery } from './middleware/validate.js'

router.get('/news', validateQuery(paginationSchema), async (req, res, next) => {
  const { page, pageSize } = req.validated.query
  const data = await postRepository.getNews({ page, pageSize })
  res.json({ code: 0, message: 'ok', data })
})
```

> `req.validated.query` 是校验后的归一化结果（数字已转 number）；不要依赖 `req.query` 的字符串值，也不要给它赋值（Express 5 中为只读）。

错误响应由 `errorHandler` 统一输出，格式为 `{ code, message, data: null }`。

## 9. 重建数据库

```sql
DROP DATABASE IF EXISTS pami_portal;
CREATE DATABASE pami_portal DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

然后重新执行 `npx prisma migrate deploy` 与导入脚本即可。
验收要求「数据库可以通过迁移脚本重新创建」即指此流程。

2. 李悦涵/赵天硕更新 `database/seed/initial-data.json` 中的对应字段。

## 11. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `P1001: Can't reach database server` | MySQL 未启动或端口/主机错误 | 启动 MySQL，核对 `DATABASE_URL` |
| `P2025` 或接口 40401 | `site_settings` 没有导入 | 执行导入脚本 |
| 中文乱码 | 库/表字符集不是 utf8mb4 | 重建库为 `utf8mb4_unicode_ci` |
| `prisma migrate` 提示 schema 漂移 | 手工改过表 | 用 `prisma migrate diff` 对齐，或重建库 |
| 前端请求被浏览器拦截 | `CORS_ORIGIN` 未包含前端地址 | 在 `.env` 中补充，逗号分隔 |
| 接口返回 `null` | Repository 未取到配置行 | Controller 转 `ApiError.notFound` 或返回空结构 |
| 导入脚本提示 `ER_DUP_ENTRY` | 未使用 `--reset` 且手工改过唯一键 | 加 `--reset` 或在数据文件里修正 `slug` / `code` |
