# 数据库初始化及使用说明

> 本文档面向后端负责人与数据层负责人；联调环境完成后请提交 Pull Request 至 `develop` 分支。

## 1. 前置要求

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 18 | 建议 v20 LTS |
| npm | 随 Node | — |
| MySQL Server | ≥ 8.0 | 字符集 utf8mb4_unicode_ci |
| Prisma CLI | 随 `backend/package.json` | `npm install` 后可用 `npx prisma` |

## 2. 创建数据库与账号

```sql
-- 在 MySQL root 下执行
CREATE DATABASE IF NOT EXISTS pami_portal
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

-- 本账号只需要对 pami_portal 的增删改查与迁移权限
CREATE USER IF NOT EXISTS 'portal_user'@'localhost' IDENTIFIED BY 'change-me';
GRANT ALL PRIVILEGES ON pami_portal.* TO 'portal_user'@'localhost';
FLUSH PRIVILEGES;
```

**生产账号**由运维单独配置，禁止使用 root 账号。

## 3. 配置环境变量

```bash
cd ceshi/backend
cp .env.example .env
# 编辑 .env，把 DATABASE_URL 里的 change-me 换成上面创建的密码
# 如果 Prisma 连接时遇到"Public Key Retrieval is not allowed"，把连接串加上 ?allowPublicKeyRetrieval=true&useSSL=false
```

## 4. 建表与导入

### 方式 A：Prisma 迁移（推荐）

```bash
cd ceshi/backend
npm install
npx prisma generate                     # 生成 @prisma/client
npx prisma migrate deploy                # 执行迁移 20261104000000_init
node ../database/scripts/import-data.js --set=mock --reset   # 导入模拟数据
```

### 方式 B：无法运行 Prisma 时，用兜底 DDL

```bash
mysql -u portal_user -p pami_portal < ceshi/database/schema.sql
node ceshi/database/scripts/import-data.js --set=mock
```

### 切换正式数据

```bash
# 清空并导入正式初始数据（联系邮箱为空、文章为空）
node ../database/scripts/import-data.js --set=initial --reset
```

导入脚本是**幂等 upsert**——`site_setting` 固定 id=1、`business_directions` 按 `code`、`external_links` 按 `name`、`posts` 按 `slug`。重复执行不会重复插入。

## 5. 数据交接

### 公开接口与数据库表映射

| 公开接口 | 查询表 | 过滤条件 | 排序规则 |
| --- | --- | --- | --- |
| `getSite()` | `site_settings` + `external_links` | `is_active=true` | `primary DESC, sort_order ASC` |
| `getHome()` | `site_settings` + `business_directions` | `is_active=true` | `sort_order ASC` |
| `getAbout()` | `site_settings` | — | — |
| `getBusiness()` | `business_directions` | `is_active=true` | `sort_order ASC` |
| `getProjects()` | `posts` | `type=achievement,status=published` | `sort_order ASC → publishedAt DESC → id DESC` |
| `getNews(p,ps)` | `posts` | `type=announcement,status=published` | **is_pinned DESC** → publishedAt DESC → sort_order ASC → id DESC |
| `getRecruitment(p,ps)` | `posts` | `type=recruitment,status=published` | `sort_order ASC → publishedAt DESC → id DESC` |

### 排序与分页约定

- **排序在数据库侧完成，不允许服务层查全表后内存排序/分页**。
- 公告有 `is_pinned` 字段，置顶优先于任何时间排序。
- 分页参数在 Repository 侧归一化：`page` 最小 1，`pageSize` 最小 1、最大 100，默认 20。
- `draft` / `offline` 状态的文章不会被公开接口返回。

### 隐私约束

| 类别 | 处理方式 |
| --- | --- |
| 成员个人资料 | 一期不建 members/admins 表；团队只返回职能说明 |
| 个人联系方式 | 不导入成员手机号/邮箱；`site_settings.contact_email` 正式数据为空，内容负责人确认可公开后再填 |
| 财务信息 | 种子数据**严禁**出现银行账户、开户行 |
| 图片 | 数据库只存路径，公开接口不返回二进制 |

### 正式种子数据何时切换

- **mock**：开发联调阶段用。带测试数据，便于前端 mock 占位。
- **initial**：内容负责人提供正式文案后切换。`contact_email` 留空、`posts: []`，文章首发内容由内容负责人另行提供后导入。

## 6. 常见问题

**Prisma CLI 报"network error while attempting to run prisma generate"**
→ Prisma 首次运行需要下载引擎二进制，沙箱或内网可能阻断。改用方式 B（直接 schema.sql）即可，功能等价。

**导入脚本报 P2002 Unique constraint**
→ 同一条 seed 数据重复执行导致 upsert 与已存在记录冲突？加 `--reset` 清空再导入。

**接口返回空**
→ 检查：① `status` 是否为 `published`；② 文章类型是否匹配（announcement/achievement/recruitment）；③ 是否执行了 `--set=initial` 后又忘了填 posts。
